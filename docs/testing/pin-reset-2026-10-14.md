## B. Why (the whole PIN chain, reviewed)

1. **No reset existed.** The auth package has forgot-PIN functions (`initiatePINReset`, `verifyPINResetOTP`, `completePINReset`) but nothing called them, and the first one answered an unlocked PIN with "Reply reset PIN to continue", a loop of its own. A forgotten PIN could not be recovered by any customer, ever.
2. **No hook knew the words**, so "Reset pin" and "Me for my password what to reset" went to the model, which invented a command ("Type reset PIN") and repeated it, because the same words came back.
3. **The locks had no exit.** 5 wrong PINs lock for 15 minutes; 10 lock for 365 days "requiring OTP reset", which did not exist. The messages said "Please try again later".
4. **A wrong PIN in a purchase threw the purchase away** (airtime, data, electricity, fuel, voucher gift): state cleared, "Invalid PIN … Please try again later", sent through a once-only sender, so a repeat failure could get no reply.
5. **Asking for help at the PIN prompt dropped the withdrawal** (the sentence escaped the state), so even a working reset would have left her to start again.

## C. What changed (live from the commit in §E)

- **"Forgot PIN" works from anywhere, in her words.** "Reset pin", "Reset pin 2006", "Me for my password what to reset", "I forgot my PIN", "change my PIN", "my PIN is not working", "ek het my pin vergeet", and the like; never a voucher PIN, token or meter. Inside a flow (the PIN prompt included) it runs before every escape; outside it runs before the AI.
- **The reset:** a 6-digit code is sent to her WhatsApp number in a separate message (the same code system as sign-up: 5 minutes, "resend"); when an ID or passport is on file for withdrawals, the **whole** number (checked against the encrypted copy; the last digits the chat shows elsewhere are not enough); then the new PIN twice (1234, 0000 and the like refused). The lock is cleared, the change is audited, and **a withdrawal waiting for her PIN is waiting again**: "Your withdrawal of R342 is still waiting. Enter your new PIN to finish it." A purchase is asked again (its quote expires in minutes).
- **The cool-off (security):** the code goes to the same WhatsApp that asked for it, so on its own it proves little. After a reset **without** an ID check, withdrawals can only go to an account or number saved before the reset, for 24 hours, and the chat says so with the time. Lisa has no ID on file (she never saved one), so after her reset a withdrawal to her (unsaved) Capitec account waits 24 hours. Vercel `WAPAY_PIN_RESET_COOLOFF_HOURS` sets the hours; `0` switches it off.
- **A wrong or locked PIN never ends a flow** and always says what to do: "❌ That PIN is not right. Try again, or reply "cancel". Forgot it? Say *forgot PIN* and I will help you set a new one."
- **The chat cannot send anyone round in a circle again:** a reply that asks the customer to type the words they just sent is never sent; she gets an honest line, and a person is alerted.
- **The AI knows the real command** ("forgot PIN" is in the capability registry) and the help menu lists it.

## D. The founder's questions

**OTP by SMS or WhatsApp?** WhatsApp today: WaPay has no SMS provider. A code by SMS would add one real check (the SIM, not just a WhatsApp session that may be open on another device) and needs a provider account (about R0.20 to R0.35 per SMS); it is a small change once one exists. Either way the code lands on the same phone a thief would hold, which is why the whole ID number (when on file) and the cool-off (when not) carry the real protection.

**Remove the PIN?** Not recommended. With withdrawals open to every customer and identity checks off, the PIN is the only thing between an unlocked or borrowed phone (or a WhatsApp Web session left open) and a PayShap to someone else's account. What hurt Lisa was the missing reset, not the PIN. If the PIN feels heavy for small purchases, a later option is no PIN for airtime and data under a small amount (for example R50), and always a PIN for withdrawals and sends.

## F. Adversarial review (read-only, 2026-10-14) and what was done

| # | Finding | Done |
|---|---|---|
| 1 | The ID challenge (last 3 digits) is shown in chat elsewhere and an SA ID's tail is guessable; failures reset with every code | The whole number, checked against the encrypted value; failures counted per account over 24 hours across resets; 3 = paused + a person |
| 2 | The code goes to the same WhatsApp, so it proves little; no ID on file = no second check; the ID read failed open | A read error stops the reset; a reset without an ID check starts the 24-hour cool-off on new withdrawal destinations (env switch) |

| 5 | "My new pin is 2580" was handed off and looped | The code and the PIN are read out of a sentence; only words without digits leave the step |
| 6 | A resumed purchase lands on an expired quote | Only withdrawals and pay links resume; a purchase is asked again |
